# Requirements traceability

“Partial” means useful functionality exists but one or more requested outcomes remain unimplemented or unverified.

| Area | Coverage and status |
|---|---|
| Dashboard | **Partial.** Application totals, due follow-ups, upcoming interviews, pipeline, profile completeness, and activity are computed from account data in `app.js`; no calendar integration or unified activity log. |
| Profile and evidence | **Partial.** Per-account profile CRUD, evidence vault, role maps, and manual evidence links exist. Dashboard outcome summaries aggregate repeated role-map gaps and interview coaching feedback, but do not link the same evidence to a specific application or hiring outcome; resume extraction provenance remains incomplete. |
| Outcome intelligence | **Partial.** The dashboard aggregates saved stage counts, repeated role-map evidence gaps, and recurring coaching improvements from completed interviews, scoped to the authenticated account. No explicit outcome event links hiring results to specific evidence; no persisted Skill-to-Proof Sprint exists. |
| Job discovery | **Partial.** Arbeitnow and Remotive public feeds, filters, ranking, dedupe, attribution, and provider warnings exist. Listings can be stale/unverified and depend on network availability. |
| Resume/JD analysis | **Partial.** PDF/DOCX/TXT upload validation and analysis using supplied content with AI or labeled local heuristic. Persistent, account-scoped review records, source-line accept/reject/edit decisions, candidate confirmation, approved-copy persistence, and sanitized DOCX/PDF/TXT exports are implemented and API-tested. Generated DOCX and PDF files are opened and inspected by tests. TXT, PDF, DOCX, Unicode, table, malformed, unsupported, and oversized fixtures are covered by the API suite. Interactive Playwright execution is not locally possible without OS Chromium libraries; detailed section advice and live-provider behavior remain unverified. |
| Applications | **Implemented.** CRUD, status, priority, dates, recruiter fields, search/filter/sort, CSV, and per-account isolation; covered by API tests. |
| Career studio | **Partial.** Editable/copyable drafts for outreach, referrals, resume, portfolio and interview prep with AI or labeled fallback; only portfolio case studies are persisted. |
| Portfolio | **Partial.** Editable case-study drafts can be saved, reopened, updated, deleted, and linked to a user's own project evidence; the full structured portfolio schema and export package remain incomplete. |
| Interview | **Partial.** Role/company/JD/resume/type/difficulty/duration/mode, 25 questions, coaching, reports, and history are present. Duration is descriptive, live journey and retry behavior need E2E coverage. |
| Realtime voice | **Partial.** Backend temporary-credential endpoint and browser WebRTC flow exist; live provider/microphone path was unavailable for verification. |
| Security | **Partial.** PBKDF2 hashes, signed expiring tokens, account-specific DBs, private-route auth, input checks, upload validation, CSP/permissions/security headers, process-local throttling, tested logout revocation, and role/evidence ownership checks. Recovery, secure cookies, distributed limits, CSP style hardening, and production controls remain. |
| AI | **Partial.** Server-side OpenAI-compatible API, output validation, explicit fallback behavior, and centralized instruction to treat supplied materials as untrusted evidence. Live provider quality, adversarial prompt robustness, privacy/retention and cost controls are not verified. |
| Persistence | **Partial.** Per-user SQLite data and additive schema upgrades; no PostgreSQL/Alembic migration or backup/restore verification. |
| UI/UX | **Partial.** Isolated current-checkout browser smoke covered account registration, application creation, dashboard count update, and viewport widths 390/834/1440 with no horizontal overflow. Keyboard-only, screen-reader, contrast and full workflow checks remain incomplete. |
| Deployment | **Partial.** Docker files, persistent volume, environment documentation, and health endpoint exist; Docker CLI is unavailable, so Compose/image validation and deployment were not verified. |
| Interview report persistence | **Implemented for tested paths.** Added API test for report persistence across a new client and account isolation. Full UI interview progression remains untested. |
| 25-question generation | **Implemented for tested paths.** Added mocked test that accepts exactly 25 questions and rejects 24; live AI generation and quality remain unverified. |
| Resume extraction | **Partial.** Added valid TXT extraction test and retains invalid PDF rejection test; valid PDF/DOCX fixture coverage and OCR remain absent. |
| First-login profile onboarding | **Implemented for tested API/browser paths.** Completion state persists in the existing profile row, incomplete accounts are blocked from workspace APIs, profile drafts survive reload, and existing complete profiles are backfilled. API regression and isolated browser flow passed; screen-reader/full keyboard coverage remains incomplete. |
| Resume evidence review and candidate-approved edits | **Implemented for tested API paths.** Per-account SQLite records persist source role/JD/resume, analysis, candidate evidence decisions, line edits, and finalized copy. Tests cover ownership, strict validation, source preservation, confirmation before accepting changed text, mocked AI response validation, and DOCX/TXT exports with sanitized filenames. Browser E2E of the new edit workflow, PDF export, and live AI remain unverified. |
| Credential handling | **Fixed in checkout; action required.** Replaced real-looking values in `.env.example` with placeholders. Revoke/rotate exposed keys and verify repository history. |
| Requested technology stack | **Not implemented.** React/TypeScript/Vite/Tailwind/PostgreSQL are not present. Retaining the existing functioning stack is documented in [ARCHITECTURE.md](./ARCHITECTURE.md) and [IMPLEMENTATION_PLAN.md](./IMPLEMENTATION_PLAN.md). |
